# House rules

For anyone, human or agent, who works in this repo. Read this first.

## Hard rules

Each rule has, or will have, an automatic check. A rule without a check is only a wish, so the check is listed next to it.

| # | Rule | Check | Since |
|---|---|---|---|
| 1 | **No personal information** in the repo or its history: no names, e-mail addresses, home paths, private network addresses, machine names, account names or keys. Machine addresses and keys live only in git-ignored `*.local.*` files. Examples use documentation values (`localhost`, `192.0.2.x`, `user@example.com`). Commits are made under the neutral identity, never a personal one. | `scripts/privacy_guard.py`, run by the hooks: `pre-commit` and `pre-merge-commit` (file contents, file names, commit identity), `commit-msg`, and `pre-push` (every object in history plus the working tree). Files it can't scan (binaries, documents) are refused. | P0 |
| 2 | **Hidden checks never reach the model under test.** Checks and reference solutions are never inside the attempt container. At grading, the model's code runs only as `nobody` through `tests/sandbox.py`, never loaded into a checking process, and can reach neither /tests nor the result. Known limit: where a check runs the job's own tests over the model's code (T12, T14, T16, T19), that test run's report is written by a process the model's code runs in, so a deliberate forgery could pass that one check; the job's other checks still grade the outputs directly, a conftest.py above the tests folder is not loaded, and the transcript would show the forgery. | `dbench leaktest` (the attempt container), the job validator (the verifier kit is unchanged; no loader calls in test files), and the `tamper.sh` / `plant.sh` probes in `dbench selftest`. | P1 |
| 3 | **Every check is tested both ways** before a task can be scored: the reference solution passes every required check; doing nothing and every known cheat fail exactly their declared checks. | `dbench selftest` | P1 |
| 4 | **Synthetic or openly licensed data only**, generated by committed, seeded scripts. No proprietary or vendor data, ever. Published standards and papers (such as the ISDA CDS Standard Model's documents) are not data: a job may use them only through the download script, each with a checksum (docs/PLAN-V2.md section 2.3, point 8). They are never part of a job's folder; T11's two are shipped unchanged in documents/, outside the licence (owner's decision, 24 Nov 2026). | A test that regenerates every task's data and compares hashes; fetched documents are checked by their checksums instead (added in v2's phase V1). | P2 / v2 |
| 5 | **Only the grader marks a run delivered.** The agent's own claim is stored separately and is graded only where a job declares a claim check (T18 and T20 ask the model to name the item it held back); a claim check is a required check with a quoted brief and a frozen match rule. Scoring rules are versioned and frozen before a scored run. | Result files carry the scoring version and hash; the report refuses to mix versions. | P1 / P4 |

## Setting up a clone

```
git config core.hooksPath scripts/hooks
git config user.name "deliverbench"
git config user.email "maintainer@deliverbench.invalid"
mkdir .privacy        # then create .privacy/denylist.local.txt (one personal term per line; may be empty)
uv sync
uv run pytest
```

The denylist is git-ignored and never leaves your machine. Plain lines match as case-insensitive substrings; lines starting with `re:` are regular expressions. Your OS user name, machine name and the hosts in `endpoints.local.toml` are added automatically at scan time.

## Working rules

- **One feature at a time.** Finish it and check it before starting the next.
- **Branches.** Each phase is built on its own branch and merged into `main` only at its gate, with a merge commit and a tag.
- **Test the test.** When a check is first written, run it against something broken (it must FAIL) and against the working thing (it must PASS).
- **Fix the harness, never the answer.** If a model is treated unfairly by the harness, fix the harness for every model. Never loosen a task's checks to make a result look better.
- **STATUS.md is updated in the same commit** as the work it describes.
- **Commit messages:** a short imperative subject line; the body says why.

## Useful commands

```
uv run pytest                                      # all tests
uv run python scripts/privacy_guard.py --tree      # scan the working tree
uv run python scripts/privacy_guard.py --history   # scan every commit and tag (before any push)
```
